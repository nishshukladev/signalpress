## Papers worth a skim

- **[Zero-Mem: Zero-Token Memory Operations for LLM Agents](https://arxiv.org/abs/2607.29377)** `[deep,high_value]`
  Zero-Mem proposes zero-token memory operations for LLM agents, allowing agents to store and retrieve context without consuming prompt tokens. The technique decouples memory from the input sequence, potentially enabling longer-running agents with bounded context windows. Long-running agents hit context limits fast; this approach could let you build stateful agents that maintain memory across sessions without bleeding tokens.
  Apply ▸ [read] Read the Zero-Mem paper, identify the core memory encoding scheme, and sketch how you would integrate it into an existing agent framework like LangChain or Semantic Kernel. — via **Zero-Mem (arxiv:2607.29377)**
- **[TurnSight: Turn-Level Hindsight Self-Distillation for Tool-Integrated Reasoning](https://arxiv.org/abs/2608.04007v1)** `[deep,high_value]`
  TurnSight introduces turn-level hindsight self-distillation for tool-integrated reasoning, providing denser credit assignment than trajectory-level RL. It derives privileged context from the agent's own state rather than ground-truth answers, improving sample efficiency in multi-turn tool use. Fine-grained credit assignment is critical for training agents that use tools; this method offers a concrete recipe to improve agent learning without expensive human labels.
  Apply ▸ [read] Read TurnSight (arxiv:2608.04007), compare its hindsight mechanism to OPSD and trajectory-level methods, and outline how to apply it to a tool-use RL loop in your agent setup. — via **TurnSight**
- **[Test-Time Scaling in Reasoning LLMs: Inference Regimes, Evaluation, and Reproducibility](https://arxiv.org/abs/2608.04001v1)** `[hot,deep,high_value]`
  This paper systematically categorizes test-time scaling regimes (single-trajectory deliberation, voting/verification, partial-state search) and shows their statistical structure and compute accounting differ significantly. It provides reproducible recipes and highlights that treating all test-time compute as interchangeable leads to misoptimization. You need to choose the right test-time scaling strategy for your latency and accuracy budget; this paper gives you a framework to make that choice quantitatively.
  Apply ▸ [read] Read the test-time scaling paper (arxiv:2608.04001), identify which inference regime fits your serving constraints, and benchmark at least two regimes on a task from your domain. — via **Test-Time Scaling paper (arxiv:2608.04001)**
- **[When Attention Goes Blind: Numerical Failure in ALiBi Positional Encodings](https://arxiv.org/abs/2608.03994v1)** `[deep,high_value]`
  ALiBi positional encoding suffers from a numerical underflow failure mode where linear bias scaling zeroes out attention weights, rendering affected heads partially blind. The paper characterizes this failure and evaluates four mitigation strategies, with evidence from pretraining experiments. If you're serving or training ALiBi-based models, silent attention failures can degrade quality; knowing the failure mode and mitigations lets you avoid subtle production issues.
  Apply ▸ [micro-exp] Inspect attention weights in your ALiBi-based model (e.g., BLOOM, MPT) for near-zero patterns at long context, apply the recommended mitigation (e.g., rescaling bias), and measure perplexity change. — via **ALiBi underflow paper (arxiv:2608.03994)**
- **[Sparse Weight Decomposition for Efficient Circuit Extraction](https://arxiv.org/abs/2608.03913v1)** `[deep,high_value]`
  Sparse Weight Decomposition (SWD) reparameterizes pretrained linear layers by factorizing each weight matrix into sparse components, enabling circuit extraction without training auxiliary sparse models. This avoids the fidelity gap and extra compute of SAEs while exposing interpretable units in dense transformers. Circuit extraction is valuable for debugging and alignment work; SWD gives you a zero-training, drop-in method to analyze pretrained models you already have.
  Apply ▸ [weekend-build] Implement SWD factorization for one MLP layer in a pretrained model (e.g., GPT-2), extract top-k sparse components, and visualize which components activate for specific input patterns. — via **Sparse Weight Decomposition (arxiv:2608.03913)**
- **[Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for Prefill Reuse](https://arxiv.org/abs/2608.03893v1)** `[hot,deep,high_value]`
  Cross-model KV cache transfer reuses KV cache from one model to another in the same family (e.g., Qwen3 14B→32B), skipping prefill when swapping models mid-conversation. A closed-form linear mapping achieves this with minimal perplexity increase, saving significant compute in cascading and routing scenarios. Production systems often cascade between model sizes for cost-quality tradeoffs; skipping prefill on every swap directly reduces serving latency and cost.
  Apply ▸ [weekend-build] Implement the closed-form KV transfer mapping from the paper (arxiv:2608.03893) for Qwen3 14B→32B, benchmark prefill savings on a long conversation, and measure perplexity degradation. — via **Cross-Model KV Cache Transfer (arxiv:2608.03893)**
- **[Omega-S: A Functional Resilience Index for LLM Fine-Tuning](https://arxiv.org/abs/2608.03887v1)** `[hot,deep,high_value]`
  Omega-S is a drop-in fine-tuning regularization penalty computed from weight matrices alone (no Fisher, no old weights, no prior-task data), retaining more original capability during domain adaptation. On Llama-3-8B code→prose fine-tuning, it outperforms EWC, L2, and LoRA-only baselines with <4% overhead. Catastrophic forgetting is a practical blocker for domain-specific fine-tuning; Omega-S is a three-line addition that preserves capabilities without complex setup.
  Apply ▸ [micro-exp] Add the Omega-S penalty (from arxiv:2608.03887) to your fine-tuning loop, fine-tune Llama-3-8B on a domain-specific dataset, and measure retention on HumanEval or MMLU. — via **Omega-S (arxiv:2608.03887)**

## Eval-methodology watch

- **[PAST-Bench: Benchmarking the Foundations of Recursive Self-Improvement in Personal Agents](https://arxiv.org/abs/2608.04003v1)** `[hot,deep,high_value]`
  PAST-Bench is a benchmark for recursive self-improvement in personal agents, testing whether accumulated experience (preferences, task histories, tool routines) actually improves agent performance over sequential sessions. Each task sequence is fresh and unseen, isolating whether agents learn from history. Most agent evals measure single-shot performance; this benchmark directly tests the self-improvement loop that matters for production personalization and long-term deployment.
  Apply ▸ [micro-exp] Clone the PAST-Bench repository, run the evaluation on your agent framework with memory enabled, and compare cumulative task success against a stateless baseline. — via **PAST-Bench**
- **[ContinualSkillBench: Can LLM Agents Truly Evolve Their Capabilities?](https://arxiv.org/abs/2608.03874)** `[hot,deep,high_value]`
  ContinualSkillBench evaluates whether agents can evolve skills in-context across 100 interconnected subtasks in five domains, ordered by difficulty. It measures both skill acquisition and whether resulting skills improve downstream task success, isolating genuine continual learning from prompt engineering. Skill learning is a core agent capability claim; this benchmark separates real skill evolution from memorization and lets you measure whether your agent framework actually improves over time.
  Apply ▸ [micro-exp] Clone ContinualSkillBench, run your agent framework (e.g., LangChain with memory) on one domain's 100-task sequence, and plot skill library growth vs. task success rate. — via **ContinualSkillBench**
- **[ExplainBench: Evaluating Code Explanations from Agents](https://arxiv.org/abs/2607.26451)** `[hot,deep,high_value]`
  ExplainBench evaluates the trustworthiness of agent-generated code explanations, addressing the gap between code generation evals and the growing need to understand large agent-written changes. It provides a benchmark for measuring explanation accuracy as agents take on bigger code edits. As agents write more code, manual review becomes infeasible; trustworthy explanations are critical for code review workflows, and this benchmark lets you measure explanation quality.
  Apply ▸ [micro-exp] Run ExplainBench on your coding agent's output, compare its explanation accuracy against baselines, and identify which explanation failure modes matter most for your review process. — via **ExplainBench**

## Pattern watch

**Agents + Evals (HOT, DEEP):** Three new benchmarks (PAST-Bench, ContinualSkillBench, ExplainBench) all focus on *whether agents actually improve over time* rather than single-shot performance—signaling a shift from capability demos to measuring genuine learning and self-improvement loops. **Inference Serving (DEEP, HIGH-VALUE):** Cross-model KV transfer and test-time scaling taxonomies reflect production optimization patterns—serving systems are moving beyond naive batching toward structured compute reuse and regime-aware scaling. **Practices (DEEP, HIGH-VALUE):** Omega-S and Sparse Weight Decomposition both offer zero-training, drop-in methods for fine-tuning retention and interpretability, respectively, prioritizing practicality over novel architectures.
