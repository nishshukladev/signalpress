## Papers worth a skim

- **[Change2Task: From Repository Changes to Executable Coding Agent Tasks and Environments](https://arxiv.org/abs/2607.28591v1)** `[hot,deep,high_value]`
  Change2Task converts merged pull requests into verified coding agent tasks by aligning historical evidence with evolved code and reconstructing task specs from commit diffs. It provides a scalable pipeline for generating executable, realistic coding benchmarks from real repository histories. Coding agent evals stagnate on toy problems; this gives you a reproducible method to generate domain-specific, production-fidelity tasks from your own repos.
  Apply ▸ [weekend-build] Clone the Change2Task repo, run the pipeline on a recent PR from an internal repo, and benchmark a coding agent on the extracted task. — via **Change2Task**
- **[Sample More, Reflect Less: Self-Refine and Reflexion Lose to Repeated Sampling at Equal Token Cost, from 1.5B to 7B](https://arxiv.org/abs/2607.28576v1)** `[hot,deep,high_value]`
  Study spanning 1.5B to 7B models shows self-refine and reflexion lose to repeated sampling at equal token cost, exposing that many agentic reasoning gains come from generating more text rather than the method itself. Baseline comparison that controls for token budget is essential but often omitted. You're designing agent loops: this paper teaches you to isolate method gains from brute-force sampling gains, avoiding over-engineered architectures that add complexity without real benefit.
  Apply ▸ [micro-exp] Run a pass@k baseline (majority vote over repeated samples) on one agent task before adding self-critique or multi-turn reasoning. — via **your existing agent eval suite**
- **[Frontis-MA1: Training an AI4AI Model towards Recursive Self-Improvement in Machine Learning Engineering](https://arxiv.org/abs/2607.28568v1)** `[hot,deep,high_value]`
  OpenMLE is an open full-stack system for recursive self-improvement research in machine learning engineering, pairing verifiable task environments (OpenMLE-Gym) with operator learning (OpenMLE-RL) and long-horizon search (OpenMLE-Evo). Frontis-MA1 (35B) is post-trained as a meta-evolution agent on this stack. RSI and AI4AI are frontier agent capabilities; OpenMLE gives you an executable testbed to experiment with meta-learning loops that improve ML pipelines, a scarce skill for Staff+ roles.
  Apply ▸ [weekend-build] Clone OpenMLE-Gym, run the example MLE task suite, and evaluate one agent on hyperparameter tuning or model selection. — via **OpenMLE**
- **[ORCA-bench: How Ready Are Language Model Agents for Oncall?](https://arxiv.org/abs/2607.28545v1)** `[hot,deep,high_value]`
  ORCA-bench puts coding agents into production-fidelity oncall root cause analysis, exposing live OpenTelemetry metrics, logs, traces, and source code over a six-day microservice incident timeline. Unlike toy benchmarks, it demands reasoning over noisy, multi-signal data starting from ambiguous user reports. Oncall troubleshooting is a high-stakes, real-world skill; this benchmark lets you evaluate and train agents on a task that directly maps to Staff+ engineering work.
  Apply ▸ [weekend-build] Deploy ORCA-bench locally, replay one incident scenario, and evaluate an agent's RCA trace against the ground-truth root cause. — via **ORCA-bench**
- **[TCA-SIR: Learning Target-Conditioned Abstractions for Scientific Inspiration Retrieval](https://arxiv.org/abs/2607.28498v1)** `[deep,high_value]`
  TCA-SIR learns target-conditioned abstractions for scientific inspiration retrieval, representing how a candidate inspiration transfers to a target problem rather than just topical similarity. Especially valuable for remote inspirations whose reusable principles are hidden by topic mismatch. AI for science workflows increasingly involve cross-domain inspiration; understanding transferable problem-solving principles is a deep reasoning capability that distinguishes advanced agent design.
  Apply ▸ [read] Read the TCA-SIR paper and map its abstraction framework to one cross-domain analogy in your current project. — via **TCA-SIR paper**
- **[Filesystem-Based Memory for LLM Agents: Organization, Evolution, and Sustainability](https://arxiv.org/abs/2607.26637)** `[hot,deep,high_value]`
  Study shows deployed LLM agents increasingly use filesystem-based memory (markdown files in a directory tree), yet research has not tested whether agents can keep this medium organized as memories accumulate, conflict, and go stale. Paper evaluates both organization capability and sustainability over time. If you're building long-running agents, filesystem memory is the default pattern; understanding its failure modes and organizational requirements prevents memory drift in production.
  Apply ▸ [micro-exp] Instrument your agent's filesystem memory with a snapshot script; run a multi-session task and manually audit for conflicting or stale files. — via **your agent's filesystem memory implementation**
- **[Revisiting Lossy Verification in Speculative Decoding: Mechanisms, Trade-offs, and Failure Modes](https://arxiv.org/abs/2607.26627)** `[hot,deep,high_value]`
  Paper revisits lossy verification in speculative decoding, showing that relaxing exact distributional matching can accelerate inference but silently rewrites the decoding distribution, sometimes causing severe quality degradation. Provides mechanisms, trade-off analysis, and failure-mode taxonomy. Speculative decoding is a core inference optimization; understanding when lossy verification breaks lets you deploy it safely and debug quality regressions in production.
  Apply ▸ [read] Read the paper's failure-mode taxonomy and check if your speculative decoding setup uses lossy verification; measure output divergence on a held-out task. — via **your speculative decoding implementation**
- **[BM25 Wins at Scale: A Scaling Study of Retrieval-Augmented Generation Paradigms](https://arxiv.org/abs/2607.26497)** `[hot,deep,high_value]`
  Controlled scaling study of RAG paradigms (lexical, dense, graph, agentic) across 28 corpus-size tiers spanning ~450×, holding questions and documents fixed. BM25 wins at scale under one reader and budget; dense retrieval and agentic search show different accuracy-cost trade-offs. RAG architecture choices are usually benchmarked at one scale; this study gives you empirical scaling curves to inform when to upgrade from BM25 and where agentic search pays off.
  Apply ▸ [micro-exp] Reproduce the BM25 baseline on your own corpus at two different scales and plot the accuracy-cost curve to validate the finding. — via **BM25 (e.g., Elasticsearch, rank_bm25)**
- **[OSReward: Instituting Standardized Evaluation for Cross-Platform Computer-Use Reward Models](https://arxiv.org/abs/2607.28609v1)** `[hot,deep,high_value]`
  OSReward introduces standardized cross-platform evaluation for computer-use reward models, addressing the fact that VLMs-as-judges of agent trajectories have long operated without systematic benchmarking. Provides verifiable tasks and a methodology to test reward model reliability at scale. Computer-use agents increasingly rely on VLM judges for RL and data curation; standardized reward-model evals let you choose and tune judges with confidence.
  Apply ▸ [weekend-build] Run OSReward's benchmark suite on two candidate VLM judges and compare their agreement rates on your agent's trajectories. — via **OSReward**

## Pattern watch

**Agents crossing into production-fidelity evals (HOT+DEEP):** ORCA-bench (oncall RCA), Change2Task (real PRs → tasks), OSReward (cross-platform reward models), and Qwen-UI-Agent all shift from toy tasks to realistic, multi-signal environments—oncall logs, repository histories, real device control. **Repeated sampling beats agentic reasoning at equal token cost (HOT+DEEP):** Paper #41 shows self-refine/reflexion lose to pass@k baselines when token budgets are matched, echoing the broader pattern that many "agentic" gains come from brute-force generation rather than architectural novelty. **Filesystem memory and long-horizon agent sustainability (DEEP):** Paper #56 flags that deployed agents default to markdown-in-directories for memory, yet research hasn't tested whether agents can keep this organized over time—a key gap for production longevity.
