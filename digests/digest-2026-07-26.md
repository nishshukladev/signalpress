## Papers worth a skim

- **[Dataset Distillation by Influence Matching](https://arxiv.org/abs/2607.16859)** `[deep,high_value]`
  Influence Matching introduces a sample-level differentiable influence estimator that aligns the effect of a synthetic dataset on converged parameters with that of the full dataset, bypassing gradient-matching surrogates. This approach shifts dataset distillation from process-centric to outcome-centric optimization. Offers a principled way to create compact training sets for rapid experimentation and ablations without iterative trajectory matching overhead.
  Apply ▸ [micro-exp] Reproduce the influence estimator on a small classification dataset to verify convergence-based distillation works on your domain. — via **arxiv:2607.16859 reference implementation**
- **[X$^3$-OPD: Distilling Reasoning into Large Audio-Language Models via On-Policy Alignment](https://arxiv.org/abs/2607.21550v1)** `[deep,high_value]`
  X³-OPD distills reasoning from a text-based teacher LLM into an audio-language student via on-policy alignment, generating reasoning trajectories conditioned on audio then optimizing them via policy gradients. Tackles the scarcity of audio reasoning data by cross-modal knowledge transfer. Shows a reusable pattern for bootstrapping reasoning in modalities (audio, vision) where labeled reasoning traces are scarce.
  Apply ▸ [read] Read the on-policy distillation method and adapt the trajectory-generation loop to your multimodal agent pipeline. — via **arxiv:2607.21550**
- **[What, Where, and How: Disentangling the Roles of Task, Language, and Model in Code Model Representations](https://arxiv.org/abs/2607.21491v1)** `[deep,high_value]`
  Applies mechanistic interpretability (concept-circuit extraction) across a 2×2 design (Python/Rust × Qwen/DeepSeek) to measure what depends on task, language, or model architecture. Finds three-way split: some concepts are model-specific, some language-specific, and some universal. If you're building multi-language code tools or fine-tuning code models, knowing which representations transfer helps you allocate effort and data correctly.
  Apply ▸ [read] Read the concept-circuit extraction protocol and replicate it on your own fine-tuned model to see which features are stable vs. model-dependent. — via **arxiv:2607.21491**
- **[Finite-Sample Coverage Audits for High-Recall Candidate Generation: Certification and Learning-Theoretic Design](https://arxiv.org/abs/2607.21480v1)** `[deep,high_value]`
  Characterizes label complexity for certifying high-recall candidate generation: shows labels from inside the candidate set cannot certify non-trivial bounds, but a hybrid strategy mixing in-set and out-of-set labels achieves tight complexity. Directly applicable to RAG and two-stage retrieval pipelines. Helps you design eval audits for retrieval stages that provably bound missed relevant items, critical for compliance or safety-critical RAG.
  Apply ▸ [read] Read the certification protocol and apply the hybrid labeling strategy to audit your RAG retrieval recall with finite-sample guarantees. — via **arxiv:2607.21480**
