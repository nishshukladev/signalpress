## Papers worth a skim

- **[Early Adoption of Agentic Coding Tools by GitHub Projects](https://arxiv.org/abs/2607.14037v1)** `[hot,deep,high_value]`
  This paper analyzes 25k agentic pull requests across 2,361 GitHub repos to study how coding agents are adopted and managed at project scale, revealing patterns in human-agent collaboration and project-level governance. Offers empirical data on agent integration in real repositories. Understanding adoption patterns of coding agents informs how to design and deploy them in production; directly relevant to practices and agents-evals lanes.
  Apply ▸ [read] Read the paper and extract the top 3 project-level anti-patterns to avoid when integrating agentic PRs into your team workflow. — via **arXiv:2607.14037**
- **[Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0](https://arxiv.org/abs/2607.14004v1)** `[hot,deep,high_value]`
  Terminal-Bench 2.0 tests whether agent-optimization gains compound when applied recursively over time, rather than one-shot. Most methods fail to stack improvements; the paper introduces a continual-learning lens for agent optimization. Deployed agents must be optimized repeatedly as new tasks appear; this benchmark reveals which optimizer methods actually compound vs. saturate.
  Apply ▸ [micro-exp] Clone Terminal-Bench 2.0 and run a two-round optimization loop with your preferred agent optimizer to measure compounding vs. saturation. — via **Terminal-Bench 2.0 (arXiv:2607.14004)**
- **[TRACE: Turn-level Reward Assignment via Credit Estimation for Long-Horizon Agents](https://arxiv.org/abs/2607.13988v1)** `[hot,deep,high_value]`
  TRACE introduces turn-level reward assignment via credit estimation for long-horizon agents. Outcome rewards are sparse/high-variance for multi-turn tool-calling; TRACE uses intermediate credit signals to guide RL post-training. Credit assignment is a core bottleneck in RL for long-horizon agents; TRACE offers a practical method to improve sample efficiency and reward shaping.
  Apply ▸ [read] Read TRACE paper and implement a minimal turn-level credit estimator for an existing multi-turn agent codebase using intermediate tool returns. — via **arXiv:2607.13988 (TRACE)**
- **[Generative Compilation: On-the-Fly Compiler Feedback as AI Generates Code](https://arxiv.org/abs/2607.13921v1)** `[hot,deep,high_value]`
  Generative Compilation provides on-the-fly compiler feedback during LLM decoding for languages with rich static semantics (e.g., Rust). Avoids costly reimplementation of semantic constraints in constrained decoding by querying the off-the-shelf compiler during generation. Compiler-in-the-loop generation improves correctness of AI-generated code in strict languages; directly applicable to coding-agent tooling.
  Apply ▸ [weekend-build] Prototype a Rust code-generation harness that queries rustc during sampling and rejects invalid tokens, measuring pass@1 improvement. — via **arXiv:2607.13921 (Generative Compilation)**
- **[DeepStress: Stress-Testing Deep Search Agents](https://arxiv.org/abs/2607.13920v1)** `[hot,deep,high_value]`
  DeepStress is a stress-testing framework that replaces the retrieval module of search agents with a controlled synthetic environment, enabling controlled injection of poor-quality evidence. Reveals robustness gaps in multi-step QA agents. Rare failure modes in realistic benchmarks become common in production; DeepStress offers a systematic way to test agent robustness to noisy evidence.
  Apply ▸ [micro-exp] Integrate DeepStress synthetic environment into an existing search agent and measure performance degradation under controlled noise levels. — via **arXiv:2607.13920 (DeepStress)**
- **[Partially Correlated Verifier Cascades in LLM Harnesses: Concave Log-Odds, Polynomial Reliability, and Blind-Spot Ceilings](https://arxiv.org/abs/2607.13918v1)** `[deep,high_value]`
  This paper extends the Odds Law to partially correlated verifier cascades, showing that posterior log-odds grow sub-linearly (concave) when verifiers share failure modes, and failure decays polynomially rather than exponentially. Provides a tight theory for serial verification gates in LLM harnesses. Serial verification is a core reliability primitive; understanding correlation effects prevents over-confidence in cascaded verifiers.
  Apply ▸ [read] Read the paper and compute correlation coefficients for your existing verifier cascade to determine if you're in the polynomial or exponential regime. — via **arXiv:2607.13918 (Partially Correlated Verifier Cascades)**
- **[From Noisy Traces to Root Causes: Structural Trajectory Analysis and Causal Extraction for Agent Optimization](https://arxiv.org/abs/2607.07702)** `[hot,deep,high_value]`
  This paper introduces structural trajectory analysis for agent optimization: identifying redundant/irrelevant steps in execution traces before passing them to LLM-based reflection optimizers. Improves sample efficiency and reduces overfitting to low-value failures. Reflection-based agent optimization is noisy; pruning trajectories before reflection improves signal-to-noise and training efficiency.
  Apply ▸ [read] Read the paper and implement a minimal trajectory-pruning filter for your agent's reflection loop, measuring reduction in optimizer compute. — via **arXiv:2607.07702 (Structural Trajectory Analysis)**
- **[Harness Handbook: Making Evolving Agent Harnesses Readable,Navigable, and Editable](https://arxiv.org/abs/2607.13285)** `[hot,deep,high_value]`
  Harness Handbook introduces documentation and navigation tooling for evolving agent harnesses, making large, tightly-coupled production harnesses readable and editable. Addresses the problem of locating behavior in sprawling agent codebases. Production harnesses are large and tightly coupled; tooling that maps behavior to code locations accelerates iteration and debugging.
  Apply ▸ [read] Read Harness Handbook and apply its documentation/navigation patterns to your production agent harness to improve onboarding and modification speed. — via **arXiv:2607.13285 (Harness Handbook)**
- **[Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models](https://arxiv.org/abs/2607.12463)** `[hot,deep,high_value]`
  This paper proposes function-aware fill-in-the-middle (FIM) as mid-training for coding agent foundation models. The action-observation-continuation loop of coding agents is structurally isomorphic to function call sites; FIM on code exposes this conditioning structure at scale. Standard left-to-right pretraining on code doesn't expose agent-relevant conditioning; FIM mid-training improves agent foundation model quality.
  Apply ▸ [read] Read the paper and identify which of your agent's tool-calling patterns map to FIM-trainable code structures for future pretraining. — via **arXiv:2607.12463 (Function-Aware FIM)**
