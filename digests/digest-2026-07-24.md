  OpenForgeRL is an open framework for end-to-end RL training of harness-native agents (multi-turn, tool-using, stateful) in arbitrary environments. It extends standard SFT/RL stacks to support multi-process inference harnesses (Claude Code, Codex-style) so you can train agents the way they actually run, not just on single-turn completions. If you want to move beyond supervised demos and apply RL to your harness-based coding agent, this is the first off-the-shelf framework that bridges the gap.
  Apply ▸ [weekend-build] Clone OpenForgeRL, adapt one of its example environments to your domain (e.g., a simple SWE-bench task), and run the RL training loop end-to-end. — via **OpenForgeRL (https://arxiv.org/abs/2607.21557)**
- **[Tencent WorkBuddy Bench: A Multi-Domain Coding-Agent Benchmark with Contamination-Resistant Task Construction](https://arxiv.org/abs/2607.20911)** `[hot,deep,high_value]`
  Tencent WorkBuddy Bench is a multi-domain (Code/Web/Office/Security) coding-agent eval suite where every task is reverse-engineered from a real commit or PR, ensuring contamination resistance. It ships with a unified scoring protocol and cross-model leaderboard, explicitly designed for distribution-informed (real-world) agent benchmarking. Practitioners need evals that mirror real workloads; this gives you a turnkey, contamination-resistant benchmark for coding agents across four domains—worth running on your agent stack.
  Apply ▸ [micro-exp] Clone WorkBuddy Bench, run the Code domain tasks on your agent (or a baseline like Claude Code), and compare your scores against the published leaderboard. — via **Tencent WorkBuddy Bench (arXiv:2607.20911)**
- **[NVIDIA-labs OO Agents: Native Python Object-Oriented Agents](https://arxiv.org/abs/2607.20709)** `[hot,high_value]`
  NVIDIA OO Agents is a model-agnostic Python framework where agents are native Python objects: methods are actions, fields are state, docstrings are prompts, and type annotations are contracts. Methods with "..." bodies are LLM-completed at runtime. This eliminates the split between prompt templates, tool schemas, and workflow graphs, unifying agent definition in idiomatic Python. If you're tired of YAML prompt configs and separate tool registries, this pattern gives you a Pythonic, type-safe way to define agents—worth evaluating as a cleaner DX for your agent stack.
  Apply ▸ [weekend-build] Clone NVIDIA OO Agents, port one existing agent (e.g., a tool-calling assistant) to the OO paradigm, and measure lines-of-code reduction vs. your current harness. — via **NVIDIA OO Agents (arXiv:2607.20709)**

## Papers worth a skim

- **[Windowed-MTP: Removing the Full-Context Draft-KV Tax at Million-Token Context](https://arxiv.org/abs/2607.21535v1)** `[hot,deep,high_value]`
  Windowed-MTP removes the full-context draft-KV tax at million-token scale by applying windowed attention in the MTP draft head. The paper proves that running full attention in the draft at every step causes linear read growth that dominates cost, then shows a windowed alternative that preserves most acceptance rates while making draft cheap again. If you're serving long-context workloads with speculative decoding, this technique lets you keep multi-token prediction without blowing up draft overhead—directly actionable for production inference.
  Apply ▸ [micro-exp] Reproduce the windowed-MTP acceptance-rate experiment on a million-token trace using the paper's ablation recipe; measure draft latency and acceptance rate. — via **Windowed-MTP (arXiv:2607.21535)**
- **[Agentic coding without the cloud: evaluating open-weight large language models on longitudinal data preparation tasks](https://arxiv.org/abs/2607.21482v1)** `[hot,deep,high_value]`
  This paper introduces an open-source framework and longitudinal-data-prep benchmark for evaluating coding agents on sensitive local data (no cloud API calls). It systematically tests open-weight LLMs (Qwen, DeepSeek) on realistic tasks constrained by data-governance, measuring accuracy and completion rate without third-party model access. Researchers and enterprises handling personal data need local-inference agents; this gives you both the eval harness and a replicable methodology for benchmarking them.
  Apply ▸ [micro-exp] Clone the framework, run the provided benchmark on an open-weight model (e.g., Qwen2.5-Coder), and compare results against the paper's baseline. — via **Agentic coding eval framework (arXiv:2607.21482)**
- **[Error Certificates for KV-Cache Eviction via Randomized Design](https://arxiv.org/abs/2607.21475v1)** `[hot,deep,high_value]`
  Deterministic KV-cache eviction is non-identifiable: you can't know what error you introduced because evicted values can be altered without changing what you kept. The paper proves this formally, then shows randomized (Poisson) eviction restores identifiability and enables consistent error estimation at serving time with one logit offset. If you're building or auditing KV-cache eviction systems, knowing you can't trust deterministic schemes' error estimates matters—randomized eviction gives you provable error certificates.
  Apply ▸ [read] Read Section 3 (the non-identifiability proof) and Section 4 (randomized design); implement the Poisson-eviction prototype for a toy attention workload and measure error variance. — via **Error Certificates for KV-Cache Eviction (arXiv:2607.21475)**
- **[Test-Time Scaling via Error Localization](https://arxiv.org/abs/2607.21453v1)** `[hot,deep,high_value]`
  TTEL (Test-Time Scaling via Error Localization) assigns token-level credit to identify which reasoning steps are wrong, then resamples only broken prefixes. Unlike independent sampling or full-trajectory refinement, TTEL avoids discarding valid work, improving efficiency on coding and math benchmarks with best-of-N and multi-turn budgets. If you're scaling inference-time compute for reasoning tasks, this technique shows how to allocate retries surgically—useful for eval harnesses and production agents with latency budgets.
  Apply ▸ [micro-exp] Reproduce the GSM8K or HumanEval ablation from Section 5.2 using TTEL's error-localization recipe; compare pass@N efficiency against baseline sampling. — via **TTEL (arXiv:2607.21453)**
- **[AREX: Towards a Recursively Self-Improving Agent for Deep Research](https://arxiv.org/abs/2607.21461)** `[hot,deep,high_value]`
  AREX is a recursive self-improving research agent that decomposes deep research into constraint-satisfaction, verifies partial answers cheaply, and uses verification feedback to guide refinement. The paper demonstrates discovery-verification asymmetry: checking a candidate against a constraint is tractable, discovering one is expensive, so AREX iterates in a verify-then-refine loop. If you're building agents for research, engineering design, or any task with hard constraints, this recursive-improvement pattern is directly applicable and comes with an eval harness (the paper's benchmarks).
  Apply ▸ [weekend-build] Implement the AREX verify-then-refine loop on a toy constraint-satisfaction task (e.g., "find a Python function that passes these three test cases"); measure iteration count vs. success rate. — via **AREX (arXiv:2607.21461)**
- **[ICAE-Bench: Evaluating Coding Agents as Interactive Project Builders](https://arxiv.org/abs/2607.21217)** `[hot,deep,high_value]`
  ICAE-Bench evaluates coding agents as interactive project builders ("vibe-coding") rather than spec-followers. Tasks require clarification, multi-turn planning, tool use, debugging, and repo-level construction from incomplete product intent. The benchmark explicitly tests the workflow shift from static instruction-following to dynamic collaboration. If you're building agents for real-world dev workflows, this benchmark measures the capabilities that matter—multi-turn interaction, requirement elicitation, and stateful project building—not just single-shot code completion.
  Apply ▸ [micro-exp] Run ICAE-Bench on a coding agent (e.g., Claude Code or an open harness) and analyze where it fails: clarification, planning, or tool use; document one failure mode as a design insight. — via **ICAE-Bench (arXiv:2607.21217)**
