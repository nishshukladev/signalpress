## Papers worth a skim

- **[Metacognition in LLMs: Foundations, Progress, and Opportunities](https://arxiv.org/abs/2607.11881v1)** `[deep,high_value]`
  Survey paper defining metacognition in LLMs: self-monitoring, confidence calibration, learning from feedback, and transparent decision-making. Systematizes what makes an LLM 'know what it knows' and how that capability can be measured and improved through post-training. Metacognition is foundational to trustworthy agents and robust evals; this paper provides a framework for measuring and improving model self-awareness that directly informs agent design.
  Apply ▸ [read] Read the paper's taxonomy of metacognitive abilities and instrument your agent or eval harness to log confidence scores and self-correction steps. — via **langfuse**
- **[Inside the Unfair Judge: A Mechanistic Interpretability Account of LLM-as-Judge Bias](https://arxiv.org/abs/2607.11871v1)** `[deep,high_value]`
  Mechanistic interpretability study of LLM-as-judge bias at the hidden-state level. Shows biases occupy tight activation clusters, admit representation-level interventions, and can be mitigated via activation steering without prompt engineering. LLM-as-judge is central to evals; this work shows you can detect and fix bias by steering activations instead of endless prompt iteration, opening a new reliability lever.
  Apply ▸ [read] Read the paper's activation geometry results and explore applying activation steering to reduce position or length bias in your LLM judge. — via **nnsight**
- **[AdvancedMathBench: A Benchmark Suite for Advanced Mathematical Proof Generation and Verification](https://arxiv.org/abs/2607.11849v1)** `[deep,high_value]`
  New benchmark for advanced mathematical proof generation spanning multiple disciplines, with granular evaluation beyond final-answer correctness. Addresses gap in understanding LLM capabilities on graduate-level math reasoning. Raises the bar for reasoning evals; provides multi-step verification methodology applicable to any domain requiring rigorous process evaluation, not just outcome checking.
  Apply ▸ [read] Review the benchmark's process-based evaluation protocol and adapt it to score intermediate reasoning steps in your domain-specific eval harness. — via **inspect_ai**
- **[An Exact Instrument for State Usage in Selective State-Space Models, and the Input-Driven Migration It Reveals](https://arxiv.org/abs/2607.11796v1)** `[deep,high_value]`
  Exact instrument for measuring how Mamba-style SSMs use their state channels. Provides per-mode output decomposition and offline ablation at any budget via Gram tensor, validated against true retraining. Reveals input-driven mode migration patterns. SSMs are increasingly important for long-context serving; this tool lets you profile and optimize state usage without expensive retraining—critical for inference engineers.
  Apply ▸ [read] Read the paper's Gram tensor methodology and apply it to profile state channel usage in a deployed Mamba or Mamba2 model for optimization insights. — via **mamba-minimal**
- **[When Local Monitors Miss Compositional Harm: Diagnosing Distributed Backdoors in Multi-Agent Systems](https://arxiv.org/abs/2607.11751v1)** `[deep,high_value]`
  Identifies "distributed backdoors" in multi-agent systems: harmful payloads split across agents pass local monitors but assemble into attacks. Shows per-message safety checks have a fundamental blind spot to compositional harm. Critical for anyone building multi-agent systems with safety monitors; demonstrates that agent-by-agent checks are insufficient and you need cross-agent provenance tracking.
  Apply ▸ [micro-exp] Instrument your multi-agent system to log message lineage and test whether a split harmful payload (e.g., SQL injection fragments) bypasses per-agent checks. — via **langsmith**
- **[Proxy Exploration and Reusable Guidance: A Modular LLM Post-Training Paradigm via Proxy-Guided Update Signals](https://arxiv.org/abs/2607.11505)** `[hot,high_value]`
  PUST: decouples exploration from policy updates in post-training by using a proxy model to generate optimization signals that transfer to the target model. Enables async signal generation, reuse, and cross-model transfer—breaking the expensive exploration-on-policy bottleneck. Post-training is increasingly central to shipping; this pattern lets you amortize expensive rollouts across multiple policy updates and models, directly cutting iteration cost.
  Apply ▸ [read] Read the PUST methodology and evaluate whether your RLHF or DPO loop can benefit from proxy-based rollout generation to decouple exploration from policy updates. — via **trl**
- **[Weak-to-Strong Generalization via Direct On-Policy Distillation](https://arxiv.org/abs/2607.05394)** `[hot,high_value]`
  Shows weak-to-strong transfer via direct on-policy distillation: run RL on a small model (cheap rollouts), then distill the post-RL policy into a larger target model. Empirically effective alternative to expensive RL on the target model itself. Post-training compute is a major bottleneck at scale; this pattern offers a concrete recipe to ship improved reasoning models faster by running RL on smaller proxies.
  Apply ▸ [read] Read the distillation protocol and evaluate running RLHF on a 7B proxy model, then distilling the improved policy into your production 70B model to cut training cost. — via **axolotl**
