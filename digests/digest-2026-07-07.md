- **[Ternlight – 7 MB embedding model that runs in browser (WASM)](https://ternlight-demo.vercel.app/)** `[hot,high_value]`
  Ternlight is a 7 MB embedding model compiled to WASM that runs in the browser with no server dependency. - **[REDDIT: Correcting Model-Generated Timestamp Drift in ASR without Forgetting via Replay-Based Distribution Editing](https://arxiv.org/abs/2607.05364v1)** `[hot,high_value]`
  REDDIT corrects timestamp drift in ASR systems that emit timestamps as decoded tokens, addressing a problem where transcripts remain plausible but the time axis drifts during long non-speech spans. It uses replay-based distribution editing to fix timestamps without forgetting existing performance. Accurate timestamps unlock agentic workflows that need to align transcripts with video or multi-modal events; this technique applies beyond ASR to any autoregressive time-series model.
  Apply ▸ [read] Read the paper and audit your own ASR or audio-LLM pipeline for timestamp drift on long-gap audio samples; benchmark before/after with REDDIT's gap dataset. — via **arxiv:2607.05364**
- **[EVA-Client: A Unified Data Collection, Inference, and Deployment Framework for Embodied Policies on Real Robots](https://arxiv.org/abs/2607.02646)** `[hot,high_value]`
  EVA-Client is an open-source framework for deployment, data collection, and evaluation of manipulation policies on real robots. It decouples robot backends, inference strategies, and transport middlewares into an orthogonal grid, unifying the real-robot stages of the policy iteration loop in a single codebase. Real-robot deployment is a DX nightmare; EVA-Client's architecture offers a reusable pattern for building modular robotics tooling that ports across hardware.
  Apply ▸ [weekend-build] Clone EVA-Client, integrate your simulation policy, and run a data-collection loop on a minimal robot setup; document the integration surface area. — via **EVA-Client (arxiv:2607.02646)**

## Papers worth a skim

- **[LLM-as-a-Verifier: A General-Purpose Verification Framework](https://arxiv.org/abs/2607.05391v1)** `[hot,deep,high_value]`
  LLM-as-a-Verifier proposes a general-purpose verification framework that provides fine-grained feedback for agentic tasks without extra training, positioning verification as a new scaling axis alongside pre-training and post-training. Unlike standard LM judges, it decomposes solutions into sub-steps and validates each against an oracle, improving test-time compute. Verification unlocks self-correction loops for agents; implementing this framework gives you a reusable eval harness that scales with inference budget.
  Apply ▸ [weekend-build] Reproduce the paper's decomposition-and-verification loop on a coding-agent eval (e.g., SWE-bench-lite), measure pass@k improvement, and publish results. — via **arxiv:2607.05391**
- **[CompactionRL: Reinforcement Learning with Context Compaction for Long-Horizon Agents](https://arxiv.org/abs/2607.05378v1)** `[hot,deep,high_value]`
  CompactionRL trains long-horizon agentic LLMs with context compaction by summarizing previous interaction states when trajectories exceed max context length. It combines RL with learned compression, addressing the finite-window bottleneck for agents operating over hundreds of turns or extended tool-use sessions. Long-horizon agents hit context limits before task completion; mastering compaction strategies is essential for building multi-session tools and assistants.
  Apply ▸ [read] Read the paper and map its compaction strategy onto your agent's existing prompt structure; identify which interaction states can be safely summarized. — via **arxiv:2607.05378**
- **[TREK: Distill to Explore, Reinforce to Refine](https://arxiv.org/abs/2607.05339v1)** `[hot,deep,high_value]`
  TREK (Teacher-Routed Exploration via Forward KL) uses distillation for exploration rather than imitation, solving the problem that GRPO stalls on hard prompts whose solutions lie outside the student's on-policy support. It stages teacher-guided exploration to expand the student's trajectory distribution before reinforcement. When GRPO fails on hard reasoning tasks, TREK's staged exploration offers a principled way to bootstrap agents; this generalizes to any RL setup with verifiable outputs.
  Apply ▸ [read] Read the TREK paper, identify a hard prompt subset in your eval suite where GRPO plateaus, and design a teacher-routing experiment to measure coverage expansion. — via **arxiv:2607.05339**
- **[Multi-Turn Agentic Scientific Literature Search via Workflow Induction](https://arxiv.org/abs/2607.00597)** `[hot,deep,high_value]`
  PaperPilot frames scientific literature search as multi-turn workflow induction, allowing users to control, inspect, and refine search strategies explicitly rather than relying on implicit language-only reasoning. It tackles underspecified and evolving user intent through structured workflows. Explainable agent workflows are critical for high-stakes domains; PaperPilot's architecture pattern applies to any multi-turn task where users need to steer the agent.
  Apply ▸ [read] Read the PaperPilot paper and map its workflow-induction pattern onto a domain-specific search or retrieval task in your stack; prototype a control interface. — via **arxiv:2607.00597 (PaperPilot)**
- **[KVpop -- Key-Value Cache Compression with Predictive Online Pruning](https://arxiv.org/abs/2607.05061)** `[hot,deep,high_value]`
  KVpop learns a fixed-budget KV eviction policy by directly supervising keep-or-drop decisions against a future-attention target, avoiding static heuristics that poorly track token utility. It addresses KV cache growth, the major bottleneck in autoregressive decoding at long context. KV cache management is becoming a system-level skill; KVpop's learned eviction approach offers a principled alternative to heuristics like H2O or StreamingLLM.

It offers a taxonomy, geometry analysis, and cookbook for optimizer selection in large-scale model training constrained by compute, memory, tuning budget, and task diversity. Optimizer selection is now a system-level design decision; OmniOpt gives you a principled framework to navigate the fragmented landscape and justify choices in design docs.

  GORGO is a proxy architecture for cross-region LLM serving that holistically factors KV-cache locality, replica load, and variable network latency into load-balancing decisions. It optimizes for latency and TTFT in globally distributed inference services, addressing uneven load and cache concentrations. Multi-region serving is table-stakes for production LLM products; GORGO's cost model gives you a blueprint for building network-aware routing that respects cache affinity.

  UI-MOPD tackles continual GUI agent learning across multiple platforms using multi-platform on-policy distillation.
