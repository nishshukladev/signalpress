Open frontier weights let you study production-scale MoE and long-context architectures; Delta Attention and LatentMoE are named techniques worth understanding.

## Papers worth a skim

- **[The Physics of Multi-Turn Long-Horizon Planning: From Pre-training to Post-training via Single- and Multi-Teacher On-Policy Agentic Distillation](https://arxiv.org/abs/2607.24720v1)** `[hot,deep,high_value]`

- **[DataOrchestra: Learning to Orchestrate Per-Example Curation of Pretraining Data](https://arxiv.org/abs/2607.24717v1)** `[hot,deep,high_value]`
  DataOrchestra unifies preprocessing operations and learns an example-specific pipeline per pretraining example, moving beyond fixed corpus-level strategies. Demonstrates a principled, per-example curation framework that improves downstream LLM performance. Data curation is a high-leverage, under-discussed practice; this gives you a named, reproducible pattern to adapt for your own pretraining or fine-tuning workflows.
  Apply ▸ [read] Read the DataOrchestra paper, identify the orchestrator decision logic, then implement a simple version for filtering your fine-tuning dataset. — via **arxiv:2607.24717**
- **[Looping Is Not Reliability: State-Bound Evidence and Typed Revision Contracts for Agentic Code Repair](https://arxiv.org/abs/2607.24604v1)** `[hot,deep,high_value]`
  Studies the reliability gap in generate-test-revise coding agents: forced revision degrades correctness from 0.82 to 0.67 after two rounds. Proposes state-bound evidence and typed revision contracts to improve reliability, backed by a 900-trajectory study on HumanEval repairs. Coding agents fail silently in revision loops; this paper gives you measurable patterns and contracts to make looping actually improve correctness.
  Apply ▸ [read] Read the paper, extract the typed revision contract schema, then instrument your coding agent to log state-bound evidence and measure correctness across revisions. — via **arxiv:2607.24604**
- **[PIVOT: Efficient Query-Group Indexing for Token-Level Sparse Attention](https://arxiv.org/abs/2607.24593v1)** `[hot,deep,high_value]`
  PIVOT reduces the O(L²) cost of DeepSeek Sparse Attention's indexer by grouping nearby queries and amortizing top-k selection. Demonstrates 2–3× speedup on real workloads by exploiting query overlap, a concrete optimization for token-level sparse attention. Sparse attention is production-relevant; PIVOT gives you a named, implementable optimization to speed up the indexer bottleneck in DSA and similar systems.
  Apply ▸ [weekend-build] Implement PIVOT's query-group indexing for a sparse attention kernel (e.g., FlashAttention-2 with top-k), benchmark on synthetic long-context tasks. — via **FlashAttention-2 (Dao-AILab)**
- **[D-Score: A Spectral Hidden-State Signal for Hallucination Detection in Large Language Models](https://arxiv.org/abs/2607.24586v1)** `[hot,deep,high_value]`
  D-Score is a simple spectral statistic from hidden activations (single forward pass) that detects LLM hallucinations by counting singular directions above a tolerance. Offers a lightweight, geometry-based hallucination signal without external models or training. Hallucination detection is critical for production agents; D-Score gives you a zero-shot, interpretable signal you can integrate into any agent pipeline.
  Apply ▸ [micro-exp] Implement D-Score on a small model (e.g., Llama-3.2-3B), run it on a factuality benchmark (TruthfulQA), and compare ROC-AUC to a baseline heuristic. — via **arxiv:2607.24586**
- **[Characterizing Warp Divergence from Pascal to Blackwell](https://arxiv.org/abs/2607.23402)** `[hot,deep,high_value]`
  Empirical study of warp divergence across Ampere, Hopper, and Blackwell GPUs using cycle-accurate microbenchmarks and SASS analysis. Separates stable behavior from architectural change, providing actionable insights for kernel optimization post-ITS. Understanding warp divergence is essential for writing fast inference kernels; this paper gives you concrete, tested patterns across modern GPU generations.
  Apply ▸ [read] Read the paper, replicate one microbenchmark on your GPU (Ampere/Hopper), then profile a real attention kernel to identify divergence bottlenecks. — via **arxiv:2607.23402**
- **[Codifying the Judge: Scalable Evaluation via Program Distillation](https://arxiv.org/abs/2607.22561)** `[hot,deep,high_value]`
  Codifying the Judge distills LLM-as-a-judge into a committee of programs via program distillation, offering transparency, low latency, and zero generation cost. LLM-as-a-judge is expensive and opaque; program distillation gives you a named, scalable alternative that's inspectable and debuggable—critical for production evals.
