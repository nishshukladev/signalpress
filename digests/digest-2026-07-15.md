## Papers worth a skim

- **[Do AI Agents Know When a Task Is Simple? Toward Complexity-Aware Reasoning and Execution](https://arxiv.org/abs/2607.13034v1)** `[hot,deep,high_value]`
  Paper introduces complexity-aware execution-scope estimation for LLM agents, showing that agents often over-read context for simple tasks. Proposes judging task difficulty upfront to avoid unnecessary file audits during one-line edits. Agent efficiency bottlenecks are moving from inference to retrieval; scope estimation is a lever for 10x faster coding agents.
  Apply ▸ [micro-exp] Implement a prompt-based task classifier that scores edit scope before calling your agent's context-gathering step. — via **arxiv:2607.13034**
- **[PalmClaw: A Native On-Device Agent Framework for Mobile Phones](https://arxiv.org/abs/2607.13027v1)** `[hot,deep,high_value]`
  PalmClaw presents a native on-device agent framework for mobile phones, enabling LLM agents to execute tasks locally through tool-calling rather than remote APIs. Addresses latency, privacy, and offline use cases for mobile agent deployment. On-device agents are the next frontier; understanding mobile constraints shapes edge-deployment architectures.
  Apply ▸ [read] Read PalmClaw's architecture section, then map its tool-calling pattern to your own on-device inference stack. — via **arxiv:2607.13027**
- **[Form, Not Content? A Preregistered, Placebo-Controlled Evaluation of Learned Error-Conditioned Self-Repair Through Prompts and Weights in Frozen Small Code Models](https://arxiv.org/abs/2607.12962v1)** `[hot,deep,high_value]`
  PoPE (Popperian Placebo-controlled Evaluation) introduces placebo controls for measuring self-repair in code LLMs. By permuting error content, the paper isolates whether models use execution feedback operationally or simply retry with noise. Self-repair claims lack causal evidence; PoPE provides a reproducible methodology to separate real learning from lucky retries.
  Apply ▸ [micro-exp] Run PoPE's permutation protocol on your coding agent's retry loop using the paper's error-permutation script. — via **arxiv:2607.12962**
- **[MemOps: Benchmarking Lifecycle Memory Operations in Long-Horizon Conversations](https://arxiv.org/abs/2607.12893v1)** `[hot,deep,high_value]`
  MemOps benchmark evaluates long-term memory operations (create, read, update, delete, bind) in multi-session agent conversations, decomposing failure modes beyond end-to-end QA. Exposes whether agents correctly target, time, and persist memory operations. Memory-aware agents are coming; MemOps provides the first granular eval suite for lifecycle correctness, not just retrieval accuracy.
  Apply ▸ [micro-exp] Run MemOps benchmark against your agent's memory layer to identify which CRUD operations fail. — via **arxiv:2607.12893**
- **[LLM Judges Can Be Too Generous When There Is No Reference Answer](https://arxiv.org/abs/2607.12885v1)** `[hot,deep,high_value]`
  Study finds LLM judges are overly generous in no-reference settings (no ground truth), with calibration and sensitivity experiments revealing systematic bias. Proposes a two-stage pipeline to assess judge model knowledge before deployment. LLM-as-judge is infrastructure; understanding judge reliability informs when to trust automated evals vs. human labels.
  Apply ▸ [micro-exp] Run the paper's calibration protocol on your judge model using your domain's eval tasks. — via **arxiv:2607.12885**
- **[Can LLMs Write Reliable Rubrics? A Meta-Evaluation for Experiment Reproduction](https://arxiv.org/abs/2607.12835v1)** `[hot,deep,high_value]`
  First meta-evaluation of LLM-generated rubrics for paper reproduction tasks. Reformulates rubric generation as a structured task and benchmarks reliability against expert-written rubrics, exposing hallucination and granularity gaps. Auto-generating eval rubrics is a scaling lever for research agents; this paper provides baseline accuracy and failure modes.
  Apply ▸ [read] Read the rubric-generation prompt templates and error taxonomy, then apply to your paper-reproduction workflow. — via **arxiv:2607.12835**
- **[Know Before Fix: QA-Driven Repository Knowledge Acquisition for Software Issue Resolution](https://arxiv.org/abs/2607.11111)** `[hot,deep,high_value]`
  QA-driven repository exploration for software issue resolution. Instead of fix-driven context gathering, the paper first generates questions to expose agent knowledge gaps, then retrieves answers to bridge understanding deficits before repair. Agents that explore before fixing reduce hallucination; QA-driven retrieval is a reusable pattern for code agents.
  Apply ▸ [micro-exp] Implement a pre-fix QA step in your coding agent that asks clarifying questions before context retrieval. — via **arxiv:2607.11111**
- **[Multi-Agent LLMs Fail to Explore Each Other](https://arxiv.org/abs/2607.11250)** `[hot,deep,high_value]`
  Multi-agent LLMs fail to explore each other's latent strategies, leading to myopic coordination. Formalizes multi-agent exploration as a POSG problem and shows that current LLM agents exhibit polarized, suboptimal interaction patterns. Multi-agent systems are emerging; understanding exploration failure modes informs coordination architectures and eval design.
  Apply ▸ [read] Read the POSG formulation and interaction pattern taxonomy, then apply to your multi-agent eval suite. — via **arxiv:2607.11250**
- **[Metacognition in LLMs: Foundations, Progress, and Opportunities](https://arxiv.org/abs/2607.11881)** `[hot,deep,high_value]`
  Survey of metacognition in LLMs: when models know what they know, calibrate confidence, and monitor their own reasoning. Synthesizes recent work on self-assessment, uncertainty quantification, and introspective capabilities. Metacognitive capabilities are foundational for trustworthy agents; this survey maps current techniques and gaps.
  Apply ▸ [read] Read the taxonomy and implementation patterns, then instrument your agent with confidence scoring from Section 3. — via **arxiv:2607.11881**
